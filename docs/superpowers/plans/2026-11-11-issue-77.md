## Decisions made at planning (gate 1 is pre-approved; listed so gate 2 can check them)

1. **The stop is by PID, found from the port.** `kill $(lsof -ti tcp:<port> -sTCP:LISTEN)`. The Bash tool does not keep shell state between calls, so `$!` from the start call is gone by the stop call. The port is unique to the worktree, so the PID that listens on it is this worktree's server. A PID file was rejected: it needs a new ignored path.
2. **The port is 3000 plus the issue number** (3077 for #77), or the next free one up. Recent plans already used this rule (3082 for #82). The block's first line proves the port is free before the server starts.
3. **A path check confirms the stop.** `pgrep -fl "$PWD/node_modules/"` must print nothing after the kill. The process that listens is Next's child server. Next's dev parent should exit when that child exits, but this was not checked against Next's source, because no `node_modules` exists in this worktree or the main folder. The path check catches a parent that stays alive. `$PWD` is the worktree root, because every Bash call starts there.
4. **The "multiple Node processes" rule is narrowed, not kept.** The old wording ("Do NOT run multiple Node processes simultaneously") also forbade the full check itself, which runs `tsc` while the dev server is up. The new wording keeps the real rule (no `next build` beside `next dev`) and scopes it to one worktree.
5. **AGENTS.md keeps one line that names `pkill -f "next dev"`**, as the thing not to do. The Done when says the block must not *say to* kill all servers. A named warning stops a later edit from restoring the line.

## Review Focus

1. **Next's parent process outlives the killed child.** If it does, the server's port is free but a `next dev` process stays. Decision 3's path check catches this at stop time. The stand-in test in Step 3 cannot prove the Next case; the next ticket that runs a real dev server proves it. Gate 2 says this.
2. **`lsof` prints nothing for the port at stop time** (server already dead). Then `kill` gets no argument and prints a usage error. That is harmless and visible. Do not add a guard for it.

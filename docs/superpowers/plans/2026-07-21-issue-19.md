# Social Links Hover Weight (Kal Bubble Port) — Implementation Plan (issue #19)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add press-and-hold bubble weight (ported from Kal's `.cell` physics) to the three hero social links, on top of #18's brand cursors + colors.

**Architecture:** One plain CSS class `.hover-bubble` in `app/globals.css` holds all the physics (single source of truth; #20 reuses it on UTD/Soccer). It is deliberately a plain unlayered class, NOT the ticket's sketched `@utility` — SocialLink already carries Tailwind's `transition-colors` utility, and two same-specificity classes in the utilities layer setting transition longhands would race on stylesheet order. An unlayered class always beats layered utilities in the cascade, same proven pattern as the shipped `.email-google`. Wiring is per-link className in `Hero.tsx`, NOT inside `SocialLink.tsx`, because Footer also uses SocialLink and #19 scopes to the hero only.

**Tech Stack:** Next.js 16 (App Router), Tailwind v4, plain CSS in `app/globals.css`. No Framer Motion needed — Kal's physics are pure CSS.

**Done when (owner-confirmed 2026-07-21):** hero social links scale up (~1.05–1.08) on hover with the 1.56-overshoot bubble curve and sink on `:active` (0.94 + 1px, slow curve); the curves live in ONE shared utility class in globals.css that #20 can reuse; reduced-motion guard present; EMAIL variant C letter colors still work alongside the transform; owner picked a preview variant and the preview file is deleted.

## Reference physics (Kal `app/globals.css:1719-1735`, verified 2026-07-21)

- Release/settle: `transition: transform 0.30s cubic-bezier(0.34, 1.56, 0.64, 1)` — the 1.56 overshoot is the bubble pop.
- Press-in (`:active`): `transform: scale(0.94) translateY(1px)` with `transition: transform 0.45s cubic-bezier(0.16, 0.9, 0.3, 1)` — slow sink = weight.
- `@media (prefers-reduced-motion: reduce)` kills transition + transform.
- Adaptation here: Kal triggers on press only; we add a hover pop (scale UP) using the overshoot curve, keep the press-in sink on `:active`.

- [ ] **Step 1: Add `.hover-bubble` to `app/globals.css`**

Append after the `email-resolve-green` keyframes. **Substitute the `:hover` transform with the winner's value from Task 1** (shown here with Variant A; B = `scale(1.08)`, C = `scale(1.06) translateY(-1px)`). The `color 150ms cubic-bezier(0.4, 0, 0.2, 1)` term reproduces Tailwind's `transition-colors` timing, which this shorthand overrides (unlayered beats the utilities layer); without it the brand-color fade on GITHUB/LINKEDIN would snap. `display: inline-block` is technically redundant in the hero (flex items are already transformable) but makes the class safe wherever #20 drops it. `:active` is declared after `:hover` on purpose — equal specificity, later wins, so press beats hover.

```css
/*
 * Social link hover weight (Kal bubble port, #19; reused by #20). Hover pops
 * on the overshoot spring; press sinks slowly so the hold reads as weight;
 * release snaps back to the spring settle. Plain class, not @utility: it must
 * beat SocialLink's layered `transition-colors` utility in the cascade, so the
 * color timing is folded into this shorthand.
 */
.hover-bubble {
  display: inline-block;
  transition: transform 0.3s cubic-bezier(0.34, 1.56, 0.64, 1), color 150ms cubic-bezier(0.4, 0, 0.2, 1);
}
.hover-bubble:hover {
  transform: scale(1.05);
}
.hover-bubble:active {
  transform: scale(0.94) translateY(1px);
  transition: transform 0.45s cubic-bezier(0.16, 0.9, 0.3, 1), color 150ms cubic-bezier(0.4, 0, 0.2, 1);
}
@media (prefers-reduced-motion: reduce) {
  .hover-bubble,
  .hover-bubble:hover,
  .hover-bubble:active {
    transition: none;
    transform: none;
  }
}
```

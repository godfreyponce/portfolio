# Footer bottom row contrast (#85): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking. This is a **single-task plan**: per AGENTS.md it stays **uncommitted in the working tree** of branch `issue-85` for gate 2.

**Goal:** The footer's bottom row (the live commit line and "© Godfrey Ponce") reaches at least 4.5:1 on the dark footer, still reads dimmer than the handles above it, and the commit line's green and red numbers stay as they are.

**Architecture:** One class changes in one file. In `components/sections/Footer.tsx`, the bottom-row `div` swaps `text-ink-subtle` for `text-white/50`. The commit line's label text and the © span set no colour of their own, so they inherit the new one. The diff numbers set `text-diff-add` and `text-diff-del` on their own spans, and the chevron uses fixed SVG fills, so none of those change. `LatestCommitLine.tsx` and `app/globals.css` do not change.

**Tech Stack:** Next.js 16, React 19, Tailwind v4 (`@theme` tokens, `/50` opacity modifier), TypeScript.

**Spec:** Issue #85 (`gh issue view 85 --repo godfreyponce/portfolio`). Its Constraints name the fix: "Prefer the old `text-white/50`, or an existing token that passes; no new colour token unless neither works." The old footer used `text-white/50` on this row (removed in `39d2633`, #82).

## Decisions made at planning (gate 1 is pre-approved; listed so gate 2 can check them)

1. **`text-white/50`, not another token.** Ratios on `#1c1917`, computed at planning with the WCAG formula (alpha blended onto the background first):

   | Colour | Blended RGB | Ratio |
   | --- | --- | --- |
   | `ink-subtle` (today) | 120, 113, 108 | 3.65 |
   | `white/50` (pick) | 142, 140, 139 | 5.23 |
   | `surface/50` | 139, 138, 136 | 5.07 |
   | `ink-faint` (handles) | 168, 162, 158 | 6.93 |
   | `diff-add` | 63, 185, 80 | 6.88 |
   | `diff-del` | 248, 81, 73 | 5.22 |

   No existing solid token sits between 4.5 and 6.93: `ink-subtle` fails and `ink-faint` is the handles' own colour, which breaks "dimmer than the handles". `white/50` is the ticket's first preference, the old footer's value, and passes with room. `surface/50` would also pass; it is not used, because the ticket names `white/50`.
2. **No HTML variants.** The visual rule asks for variants before visual work. This ticket is one colour swap, and the owner already named the colour in its Constraints. Variants would ask the owner to pick a value they already picked.
3. **The row's border stays `border-white/10`.** The ticket covers text contrast only.
4. **The live check fakes the commit-line reply in the browser.** Without `.env.local`, `/api/latest-commit` returns no data and the commit line renders an empty `<span>`, so there is no label text to measure. Step 4 uses CDP `Fetch` interception in the headless Chrome to answer `/api/latest-commit` with a made-up payload. Nothing in the repo changes for this. The real API path is not exercised; gate 2 says so.

## Review Focus

1. **Contrast.** Expected: the computed `color` of the commit-line label span and the © span is white at 50% alpha (the exact syntax may be `oklab(...)`, see Step 2), and blended onto the computed footer background `rgb(28, 25, 23)` it gives about 5.23:1 (a blend in oklab may land a few hundredths off; at least 4.5 is the bar). Step 4 computes this from the page, not from this plan's table.
2. **Dimmer than the handles.** Expected: the bottom row's ratio (5.23) is below the handle span's ratio (6.93), both from computed colours. Step 4 prints both.
3. **Diff numbers unchanged.** Expected: the `+N` span is `rgb(63, 185, 80)` and the `-N` span is `rgb(248, 81, 73)`. Step 4 prints them.
4. **No layout change.** Expected: the footer's height and the bottom row's box are the same before and after the class swap at each width. Step 4 runs once on the unchanged tree and once after the edit, and prints both.

## Decisions made at planning (gate 1 is pre-approved; listed so gate 2 can check them)

1. **The commit-line colours stay the live tokens.** The spec colours the diff `#4ade80` / `#f87171` (`.fa .ix-add/.ix-del`). The live `LatestCommitLine` uses `text-diff-add` `#3fb950` and `text-diff-del` `#f85149`. The Done when says to use the live `LatestCommitLine`, and decision 30 says it "fills" the sample. So the component and the tokens stay unchanged. Gate 2 names this as a known difference from the spec.
2. **The chevron spacing stays the live one.** The spec puts the chevron in an `inline-flex` row with a 6px gap. The live chevron is `inline-block` with `mr-1` (4px) on the text baseline. That is a difference of 2px or less, inside `LatestCommitLine.tsx`, which this ticket does not need to touch.
3. **The page lid stays.** `main` in `app/page.tsx` keeps `border-b border-rule shadow-lid`. preview-d's `main` has neither. They show only while the footer is partly revealed, and they belong to `main`, not the footer. At full scroll the stage 3 shots show no difference. `app/page.tsx` does not change, even though the issue lists it under "Probably touches".
4. **`#top` needs no script.** The spec uses JS because a static file has no smooth-scroll rule. The site has `html { scroll-behavior: smooth }` plus `scroll-behavior: auto` under reduced motion (#78 decision 5). A plain `<a href="#top">` gives smooth and instant scroll. Unlike the spec, it adds `#top` to the URL, the same as the live footer today.
5. **The name is a `<p>`, as in the spec**, not the live `<h2>`. The footer name is not a section heading.
6. **The links use `SocialLink`** (for `target="_blank"` and `rel` on external links), with no `ariaLabel`, because the visible text now names each link. `SocialLink.tsx` does not change. Its built-in `hover:text-ink` would turn the text dark on the dark footer, so each link adds `hover:!text-surface`, the same trick the live footer uses with `hover:!text-white`.
7. **`.tactile-link` is removed from `globals.css`.** The footer icons were its only users. `.tactile-btn` stays (TheLab uses it).
8. **The footer has no base text colour.** The spec's `.fa { color: #d6d3d1 }` reaches no visible text, because every text element sets its own colour. The live `text-white` goes away.

## Review Focus

1. **The reveal leaks.** If any gap opens between the hero, `main` and the footer, the sticky footer (z-0, always pinned to the viewport bottom) shows through it. Expected: at 1440x900 and 390x844, no point above `main`'s bottom edge hits the footer at any scroll position. Step 5's hit-test scan checks this.
2. **The phone footer is too tall for the viewport.** A sticky footer taller than the viewport can never be fully seen. Expected: at 390x844 the footer is shorter than 844px, and at full scroll its bottom edge is at the viewport bottom. Step 5 checks this.
3. **Long handles at 390.** `linkedin.com/in/godfreyponce` in 13px mono must wrap (`wrap-anywhere`) and not push the page sideways. Expected: `scrollWidth <= 390`. Step 5 checks this.
4. **Link hover on dark.** Expected: on hover the link text stays `surface` (`rgb(250, 250, 249)`), and only the dashed border goes from 40% to solid. Under reduced motion, nothing transitions. Step 5 checks this.
5. **The commit line has no data.** While loading or on failure, `LatestCommitLine` renders an empty `<span>`. Expected: the row still shows "© Godfrey Ponce" on the right (desktop) or alone (phone), with no broken layout. Read this at gate 2. Do not simulate it.

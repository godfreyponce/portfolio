## Decisions made at planning (gate 1)

1. **The Visual rule changes one token: `localhost:3000` becomes `localhost:<port>`.** This matches the #77 line "Check the change visually via Chrome automation at localhost:<port>", which also uses the bare `<port>` and relies on the full check above it to define it. Adding "(see `# Verification scope`)" would push line 126 past the file's 100-column wrap and force a rewrap of line 127, which carries a pre-existing em dash.
2. **The Chrome port rule mirrors the dev-server rule:** `<cdp-port>` is 9222 plus the issue number (9308 for #86), or the next port up if another worktree has it. 9222 is the base because it is Chrome's conventional debugging port and the one the gotcha already uses. A separate placeholder name, `<cdp-port>`, keeps it from colliding with the dev server's `<port>`.
3. **The stop is `kill $(lsof -ti tcp:<cdp-port> -sTCP:LISTEN)`**, the same form as the #77 full check. The process that listens on the debugging port is Chrome's browser process; its helper processes exit when it exits. Step 2 proves this on real Chrome.
4. **The gotcha keeps one warning line that names the old `pkill`**, as #77 did for `pkill -f "next dev"`, so a later edit does not restore it.
5. **After the change, `grep -n 'localhost:3000\|9222'` still prints the new gotcha line** (it says "9222 plus the issue number"). That line is correct today, which is what the Done when asks for.

## Review Focus

1. **Chrome helpers outlive the browser process.** If they do, the port is free but processes stay. Step 2 checks for leftovers by the profile path.
2. **Two headless Chromes share a profile and the second hands off to the first.** Step 2 gives each its own `--user-data-dir` in the scratchpad. The gotcha does not add this flag: past sessions (#54, #55) ran one Chrome at a time, and the ticket does not ask for it. If Step 2 shows a hand-off without the flag, report it as a finding.

  echo "RED, the old name pattern matches both:"
  pgrep -fl 'remote-debugging-port' | grep -c "$S/chrome-"

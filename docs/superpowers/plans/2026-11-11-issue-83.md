# Issue #83: A drag that starts on a carousel's YouTube slide moves the carousel. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A mouse drag or touch swipe that starts on LAND's YouTube slide pages the carousel the same way a drag on a photo slide does, and a plain click on that slide still starts the video.

**Architecture:** The YouTube slide is a cross-origin `<iframe>` (`components/ui/MediaCarousel.tsx:234-243`). Pointer events that start inside it go to the YouTube document and never reach the Framer Motion track's drag handler (the likely cause, which Task 1 Step 1 proves or disproves before anything is written). The fix puts a transparent layer over the iframe while the video has not started. Pointer events on the layer bubble to the track, so drag works. A click on the layer that is not the end of a drag removes the layer and tells the player to play through the YouTube embed's `postMessage` command (`enablejsapi=1`). After that, the iframe gets every event, so the YouTube controls work. Paging away puts the layer back.

**Tech Stack:** Next.js 16, React 19, Framer Motion, TypeScript. No new dependency.

**Spec:** the ticket, `gh issue view 83` (no comments, no design spec). Found during #80; see `docs/HISTORY.md` lines 120-133.

## Data flow

No data-flow change: the carousel reads the same `MediaItem[]` from `lib/projects.ts` and loads the same YouTube embed. The fix changes only which element receives the pointer events inside one slide.

## Gate 1 decisions

1. **How a click starts the video once a layer covers the iframe.** Pick: add `enablejsapi=1` to the embed URL and send `{"event":"command","func":"playVideo","args":[]}` to the iframe with `postMessage`, target origin `https://www.youtube.com`. The video starts in place with no reload. If the player is not ready yet, the command is lost, but the layer is already gone, so the next click hits YouTube's own play button. Rejected: reload the iframe with `autoplay=1` on click (works every time, but flashes black for a moment while the embed reloads). That rejected option is the fallback in Task 1 Step 6 if the command does not start playback.
2. **No variants.** The ticket touches a visual component, but nothing on screen changes: the layer is transparent, and YouTube's own poster and play button show through it. The one visible difference is that YouTube's hover effects on the poster (title bar, "Watch later", "Share") do not react until the video starts, and a click on them starts the video instead. That is accepted as the cost of the fix.
3. **Only carousels with more than one slide get the layer.** A one-item YouTube carousel (TechAssist on `/projects`) has nothing to drag, so it keeps the bare iframe and YouTube's poster hover.
